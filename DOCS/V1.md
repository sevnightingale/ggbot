### Database Schema Improvements

#### Unified `decisions` Table (Replaces `strategy_runs` + `ggshot_filter`)

**Rationale**: Unify all decision tracking (signal filtering, trade entries, trade management) into a single audit trail table for cleaner architecture.

**Final Schema**:
```sql
CREATE TABLE decisions (
    decision_id UUID PRIMARY KEY,
    user_id UUID NOT NULL, -- Supabase Auth user
    config_id UUID,        -- NULL for ggShot signals (no user config)
    
    -- Core decision data
    symbol VARCHAR(20) NOT NULL,
    action VARCHAR(20) NOT NULL,          -- 'enter', 'wait', 'exit' (always present)
    status VARCHAR(20),                   -- 'approved', 'rejected' (primarily for signal validation)
    confidence DECIMAL(4,3) NOT NULL CHECK (confidence >= 0.000 AND confidence <= 1.000),
    reasoning TEXT,                       -- LLM reasoning/explanation text
    
    -- Full decision context (new audit fields)
    prompt TEXT,           -- Complete LLM prompt sent for decision
    market_data JSONB,     -- Raw indicator values used in decision
    
    -- Flexible context storage
    decision_data JSONB,   -- Type-specific data (trade_id, action, stop_loss_price, take_profit_price, etc.)
    
    -- Decision linking and audit
    parent_decision_id UUID, -- Links related decisions (entry → management → exit)
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    
    -- Row Level Security
    CONSTRAINT decisions_user_fkey FOREIGN KEY (user_id) REFERENCES auth.users(id),
    CONSTRAINT decisions_parent_fkey FOREIGN KEY (parent_decision_id) REFERENCES decisions(decision_id)
);

-- Indexes for performance
CREATE INDEX idx_decisions_user_config ON decisions(user_id, config_id);
CREATE INDEX idx_decisions_action_status ON decisions(action, status);
CREATE INDEX idx_decisions_symbol_created ON decisions(symbol, created_at DESC);
CREATE INDEX idx_decisions_parent ON decisions(parent_decision_id);
CREATE INDEX idx_decisions_confidence ON decisions(confidence DESC); -- For confidence analysis
```

### Phase 4: Orchestrator Implementation

#### GGBot Orchestrator
**Database Polling Approach**:
```python
class GGBotOrchestrator:
    async def run_autonomous_cycle(self, config_id: str, user_id: str) -> OrchestratedResult:
        # 1. Load user's config
        config = await config_repo.get_config(config_id, user_id)
        
        # 2. Trigger extraction for required indicators
        await extraction_service.extract_for_config(config_id, config.selected_pair, config.extraction.indicators)
        
        # 3. Poll database until indicators fresh (30s threshold, 70% completion)
        fresh_data = await self._wait_for_fresh_indicators(config_id, config.selected_pair, config.extraction.indicators)
        
        # 4. Run decision engine with fresh data
        decision_result = await decision_engine_v2.make_decision(config_id, config.selected_pair)
        
        # 5. Execute trading if actionable
        trading_result = await trading_service.execute(decision_result)
        
        return OrchestratedResult(fresh_data, decision_result, trading_result)
```

**Key Features**:
- Database polling instead of webhook chains
- Partial completion handling (proceed with 70% of indicators)
- Per-user context isolation
- Real-time status updates to frontend via Supabase realtime

```python
# LLM Client Factory (subscription-aware with Supabase Vault)
async def get_llm_client(user_id: str, config_id: str) -> LLMClient:
    user_profile = await get_user_profile(user_id)
    config = await get_config(config_id)
    
    if user_profile.subscription_tier == 'free':
        # Must use user's named credentials from Vault
        credential = await supabase.table('user_llm_credentials')\
            .select('vault_secret_id, provider')\
            .eq('user_id', user_id)\
            .eq('credential_name', config.llm_credential_name)\
            .single()
        
        # Decrypt API key from Supabase Vault
        secret = await supabase.rpc('get_decrypted_secret', {
            'secret_id': credential['vault_secret_id']
        })
        return create_llm_client(credential['provider'], secret['decrypted_secret'])
        
    elif user_profile.subscription_tier == 'signals':
        # Use our hosted APIs
        return create_llm_client(settings.HOSTED_LLM_KEYS)
    # Note: Premium tier removed for V1 launch
```
